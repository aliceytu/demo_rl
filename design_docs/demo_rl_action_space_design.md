# 司机侧动作空间设计讨论(2026-09-10,用户自评"勉强明白",期货讨论——当前27动作用不上)

背景: 用户问"如果司机侧5约束(trip/tr/cr/cost/tr_weekend, DRI_CONSTRAINT cafune_rl.py:2621)也交给RL怎么设计动作空间"。当前司机侧λ固定用线上值(cafune_rl.py:2774-2782),RL只调乘客3个。

## 重要代码事实修正(讨论中发现,初始说错后纠正)

- **所有约束统一是下限约束**: sp32_dri.py:911 违约判据 `inc < th` 全局适用,包括 cost
- **cost 约束 = 司机收入下限保护**(cost_th_dri 默认0,司机收入不许降),**不是**平台开销上限——ODT 是司机激励域,司机侧约束护司机。此语义易被"cost"字面误导
- **tr_weekend 在单日 episode 里是退化维**: 同一GP矩阵做周末掩码(cafune_rl.py:3103),周末日与tr完全重复,工作日全零惰性 → 有效维度=4

## 司机侧耦合结构(阵营对峙)

d=司机侧调价(加价)。TR 干净推导: **TR ≈ 1 − dri_fee(1+d)/(pax_price(1+pax)),ecr·cr在比率中约掉,TR随d单调降**。

| 阵营 | 成员 | 性质 |
|---|---|---|
| 组1(要d↑) | trip, cr, **cost(修正)** | 司机侧保护线: 单量/完单/收入 |
| 组2(要d↓) | tr(,weekend) | 平台毛利线 |

组内对齐(无谷,可坐标化),组间冲突(走廊,必须联合)。走廊对角=从两组各取一λ同动,与乘客侧(λTrip↑,λGP↑)同构。

## 核心原则(用户曾说反一次,已纠正)

> **组内坐标、组间枚举**——联合枚举是冲突方向的保险,坐标化是对齐方向的福利。刀只切耦合弱处(组内),永远不切冲突对峙的组间。谷在哪,联合就必须在哪。

## 三种接口(5λ规模,按头数排)

| 接口 | 每步动作/头数 | 要点 |
|---|---|---|
| 枚举 | 81 (3⁴) | 一步直达,配DQN最省心,**当前规模首选** |
| 省钱版(自适应坐标) | 21 = 7×3 | 7=6+1(3λ×2方向+全局不动,"最多动一个"稀疏增量);GP作第二槽每步随行("GP随行")保走廊对角原子性;"不动=不选",默认化非显式选项;组内组合多步拼装(无谷安全) |
| 扫描/自回归(MultiDiscrete) | 12头(4×3) | 固定顺序微决策构造宏动作;**红线:微步必须窗口内完成、窗口末统一执行**,跨窗口则中间态偏航吃罚;配策略方法(PPO)最自然,又是DQN→PPO的一个理由 |

## 用户理解状态与常见误区(已纠正)

- "省掉的是不变的部分"❌ → 删的是"一步动多个"(20个≥2非零组合),"不动"被默认化
- "带偏好要么向上要么向下"❌ → ±对称无偏好;真实的不对称是"选中λ必动±,不动=不选"的编码约定
- "组内枚举组间坐标"❌(说反) → 组内坐标组间枚举
- 7=6+1 数法、21=7×3 两槽乘法已明白
- 用户的检验题: (0,0,0)→(+1,−1,0) 需两步(Trip↑随GP, Cr↓随GP)

## 行动定位

当前27/81规模: 平铺枚举+DQN最省心,以上都是期货。增量路径: 乘客3维跑稳→司机侧标量力度1维(方向信求解器幅度信RL)→有肉再块结构→再大SAC连续。
