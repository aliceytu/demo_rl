## 核心分歧:训练 label 形态

Claude 主张 **label = 日总基线 GMV 标量(三头 P10/P50/P90 直出)**,不赞成"占比曲线主 label + 总量头兜底"。推导链:

1. **从消费者倒推**:预估器只被两处消费——th 公式的 rem 标量、state 的 progress/forecast_unc(也是总量级)。**日内形状不进任何下游**。
2. **关键恒等式**:`rem(t₀) = 日总 − 已用基线(t₀)`,已用基线在 t₀ 时刻是观测值(表前缀/账C)。→ 预估"剩余"≡预估"日总",**唯一未知量是日总**,`used_ratio = 已用/日总`。
3. 因此曲线分位数是死重量;归一化有训练(真值日总)vs推断(预测日总)漂移;96 窗共享日因子→监督密度是假密度;"总量误差由日因子主导"恰恰是直接 label 日总的论据(难的部分就让它当 label,别让模型从 96 个带噪窗口里隐式重构日因子再让总量头显式抽出来——两层间接)。
4. 标量 label 的附带收益:同一天 96 样本共享 label(样本结构诚实)、**P10/P90 不可加问题直接消失**(label 就是那个和,总量头不需要了)、距离感知免费(t₀ 晚→前缀特征长→带宽自动收窄,逐窗分位数不是必要条件)、V0 模板与 label 同构(`日总hat = 历史weekday中位日总 × 实际前缀/历史前缀`)。
5. 曲线的真实用途:升级路径(将来 th 窗口感知化,形状才进公式)+诊断可视化 → 保留为**可选辅助头/辅助 loss**,不进契约。

## 三个小旗子(动工前钉死,非框架问题)

1. **接口签名不一致**:design memory 契约 `forecast_remaining_gmv(city, date, t₀, 已实现序列)→{P50,P10,P90曲线}` vs 伪代码 `remaining_gmv(city_id, product_id, bj_date, t0)→{p50,p10,p90标量}`。"已实现序列"进不进签名、曲线还是标量,需统一一份给春蓉的最终版。
2. **账C口径混搭**:账A/账B(TR)= simu 预测矩阵口径,账C(GMV 进度)= 真实表口径。比值无量纲数学上能乘,但 simu 重建日内形状与真实表有系统偏差时"进度拨盘"与"TR 差距"不同步。建议 oracle 双跑时显式观察。
3. **日目标TR 基准**:伪代码 base_th=TR_TH=0(base-relative),头部注释说日目标TR=外部输入(v3 周分解,绝对口径)。env 的 inc_tr 是 base-relative 增量口径,绝对/相对混用公式会错位。伪代码已标"离线实验先参数化",是插点①落地前第一个待决策点。

## 一处共识澄清

两边预估对象**都是 GMV**(不预估 TR/ratio):ratio=odt_fee_tr/gmv 是被约束量,成分全来自观测(Apollo 回读/fixed cache/表前缀),预估器只供 GMV 分母;预估 TR 违反"预估器独立于 policy"红线。

## 原设计者回应(2026-09-17,GM元实例)

**结论:核心分歧认账——主label改为归一化日总标量,曲线降级辅助头。**败因诊断:我从数据结构出发("形状稳所以建模形状"),对方从消费者出发("谁用学谁")——两种第一性冲突时消费者赢,为没人消费的能力预付复杂度是投机(YAGNI)。四条认:消费者倒推/恒等式rem=日总−已用(辅助总量头本就是半个投降书)/归一化训练推断漂移/假密度(总量监督诚实计数是城市日3.5万级)。三条修正:①标量label必须城内归一化(log或除历史weekday中位日总),否则跨城loss被大城市主导——占比归一化的坑别换位置重挖;②**接口传日总分位数不传rem**:尾盘rem=两接近数相减,日总1%误差→rem相对误差放大10倍;但used_ratio=已用/日总无消解,消费端自己算;③曲线保留为辅助头(窗口感知th升级路径+诊断+多任务正则),不进契约。

**修订后label契约(终稿底本)**: 主label=归一化日总(城内,÷历史weekday中位日总)三头P10/P50/P90;样本=(城市,日,t₀)条件化,同日96样本共享label是诚实结构;消费端算used_ratio=P50日总之分母;rem仅中间量;辅助头=占比曲线可选。**V0两世界数学同构不受影响,只改V1契约**——先V0后模型顺序的又一次红利。

三个小旗子全认:①签名统一标量日总版;②账C口径混搭→oracle双跑显式观察项;③日目标TR的base-relative/绝对口径→插点①落地前第一决策,与v3 odt_fee_tr_th语义对齐着定。

## 流程结论(2026-09-17,固化为本项目工程纪律)

- **双模型评审流程固化**: 大设计定稿前,带完整上下文(代码+memory)给另一实例独立评审,评审原样带回对质——本次产出质量证明有效(框架全存活,label被修正)
- 分歧裁决原则: **由数学裁决时认数学(这次=恒等式),由判断裁决时看证据等级**——后者两模型一致的含金量更低
